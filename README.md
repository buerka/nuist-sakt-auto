# nuist-sakt-auto · 南信大（NUIST）实验室安全准入平台自动学习脚本

> 南京信息工程大学（NUIST）「实验室安全准入与教育平台」（https://sakt.nuist.edu.cn）的 Tampermonkey 油猴脚本：
> 自动逐节播放「未学」课时，支持 AI 答题、防挂机续播、播完自动进入下一节。
> 视频真实播放，完成记录由平台自身接口写入；脚本不伪造进度。

| 平台 | 实验室安全准入与教育平台 |

| 适用页面 | `/students/courseDetail?id=...` 课程学习页；`/students/questionList` 考试列表 / 答题页 |

该平台是南信大实验室与设备管理处使用的在线安全准入培训系统，学生需逐节看完视频并通过考试才能获得实验室准入资格。本脚本只解决「逐节连续播放」这件重复劳动。

## 功能

- **连续播放**：自动识别课程目录里所有「未学」课时，按顺序一节节播完
- **自动续播**：后台标签页 / 防挂机导致的暂停会自动恢复
- **AI 答题**：调用 OpenAI 兼容接口作答，默认「2+1」投票：先并发问 2 次，答案一致直接用，不一致再补第 3 次；多选题按 A/B/C/D 逐项计票，避免漏选
- **答题缓存**：同一道题（题干 + 选项）只请求一次 AI，答案缓存在本地，可在面板一键清空
- **自动切课**：本节 `ended` 后自动点击左侧目录进入下一节
- **考试自动答题**：识别模拟 / 正式考试的答题页，按题号顺序 AI 作答，已答题目自动跳过，可选答完自动提交
- **本地题库**：仓库附带 `sakt-bank.json`，导入后命中题目直接使用平台标准答案，不再请求 AI；未命中自动回退 AI
- **分页面板**：右下角悬浮窗分「运行 / 设置 / AI / 考试 / 题库」五页，黑白极简配色；标题栏可拖动，「−」可最小化，位置和状态会记住
- **断点续跑**：队列存在 `localStorage`，刷新页面或重开浏览器后自动从上次位置继续

## 原理

平台课程页是 Vue + 原生 `<video>` 播放器，进度逻辑在页面脚本里：

| 时机 | 平台行为 |
|---|---|
| 进入课时 | `POST /courseSource/updateVisits` |
| 每 10 秒 | `POST /courseSource/finishRate { watchDuration }` |
| 视频结束 | `POST /courseSource/finish` → 标记「学完」 |
| 弹题时刻 | 暂停视频、弹出习题，提交后继续播放 |

脚本只做三件事：**驱动播放器**（`play()` / `playbackRate` / 暂停恢复）、**点击目录树切换课时**、**点掉弹窗习题**。
不直接调用 `finish`，不修改请求内容，不伪造观看时长。

## 安装

1. Chrome / Edge 安装 [Tampermonkey](https://www.tampermonkey.net/)
2. 打开安装链接（Tampermonkey 会自动弹安装页）：

   ```
   https://raw.githubusercontent.com/buerka/nuist-sakt-auto/main/sakt-auto.user.js
   ```

   或在 Tampermonkey 面板「新建脚本」，粘贴 `sakt-auto.user.js` 全部内容保存。
3. 确认脚本已启用（图标上显示 1）
4. （可选）下载 [sakt-bank.json](./sakt-bank.json)，在面板「题库」页导入；命中题目直接用平台标准答案

## 使用

1. 登录平台，进入「我的课程」→ 任意一门课程（`/students/courseDetail?id=...`）
2. 页面右下角出现面板，点 **「开始自动学习」**
3. 保持该标签页打开（可切到后台，脚本默认静音播放）
4. 想停时点面板 **暂停 / 停止**，或控制台执行 `window.__saktStop()`

停止后再次打开课程页，会显示「开始」按钮；上次的队列仍保留，点开始即从断点继续。

## 考试自动答题

在「我的考试」列表里点「模拟考试」或「正式考试」，进入答题页后，右下角面板会自动切到「考试」页：

1. 确认面板识别到「共 N 题」和倒计时
2. 点 **「开始自动答题」**：脚本按题号 1→N 顺序答题，已答过的题目会跳过
3. 状态栏显示每题结果，例如 `第 12/45 题 → AC（AI 2/2）`；多选题的 `2/2` 是最低单项票数（分歧时可能是 `2/3`）
4. 默认**不自动提交**，检查后自己点「提 交」；勾选「答完自动提交」后，脚本答完会点提交并确认弹窗

实现上：单选题/判断题用 radio，多选题用 checkbox；多选题逐项判断 + 多次投票，「以上都是 / 以上都不对」这类互斥项只保留自身；答题记录写在 `localStorage['sakt.examlog']`。

```js
JSON.parse(localStorage.getItem('sakt.examlog')).slice(-10)
```

> 模拟考试不计成绩；正式考试平台有「不要作弊」提示，是否使用请自行评估，风险自负。
> 考试答案只存在页面内存里，**答题过程中刷新页面会丢失当前进度**，请勿中途刷新。

## 面板设置

右下角面板分五页（运行 / 设置 / AI / 考试 / 题库），所有配置存在 `localStorage['sakt.config']`，保存后立即生效。
标题栏可按住拖动，右侧「−」收起为一行，「＋」展开；位置和最小化状态存在 `localStorage['sakt.panelUI']`。

### 运行

显示剩余节数、当前课时、播放进度；提供暂停 / 停止按钮。右上角圆点绿色表示正在自动运行。

### 设置

| 项 | 默认 | 说明 |
|---|---|---|
| 播放倍速 | `1.5` | 建议 1~2；太快平台可能判异常 |
| 静音播放 | 开 | 后台标签页也能继续 |
| 自动答题 | 开 | 关闭后弹题会暂停，等你手动作答 |
| 自动切下一节 | 开 | 播完自动进入下一节 |
| 默认选项 | `A` | AI 未启用或失败时选第几个选项 |

### AI

| 项 | 说明 |
|---|---|
| 启用 AI 答题 | 打开后弹题优先请求 AI |
| 接口地址 | OpenAI 兼容的 base URL，脚本会拼 `/chat/completions` |
| API Key | Bearer Token，只存在本机 `localStorage` |
| 模型 | 例如 `deepseek-chat`、`qwen-plus`、`glm-4`；要思考模式用 `deepseek-reasoner` |
| 超时(ms) | 单次请求超时，默认 30000；思考模型建议 60000~120000 |
| 最大 tokens | 单次输出上限，默认 1024；思考模型建议 2048~4096。这是上限不是目标，调大不会让它想得更多 |
| 投票次数 | 默认「2+1」：先并发问 2 次，答案一致直接用，不一致再补第 3 次；1 次最快，3/5 次固定 |
| 额外参数 | 可选 JSON 对象，原样透传给接口，例如 `{"reasoning_effort":"high"}` |

常见接口地址示例：

```
DeepSeek     https://api.deepseek.com/v1（思考模式模型填 deepseek-reasoner）
阿里百炼     https://dashscope.aliyuncs.com/compatible-mode/v1
智谱 GLM     https://open.bigmodel.cn/api/paas/v4
Kimi         https://api.moonshot.cn/v1
本地 Ollama  http://127.0.0.1:11434/v1（模型填本地模型名）
```

> DeepSeek 的 `deepseek-chat` **没有思考开关，也没有「思考强度」参数**；要思考就把模型换成 `deepseek-reasoner`，脚本会自动省略这类模型不支持的 `temperature`。

点「测试连接」会发一条最小请求，并显示模型的回复原文、耗时和 token 数；如果提示 `finish_reason=length`，说明输出被截断，要调大「最大 tokens」。

各家思考 / 联网参数不统一，可以写进「额外参数」由脚本原样透传（不确定就留空）：

```
OpenAI / OpenRouter   {"reasoning_effort":"high"}
通义千问（百炼）        {"enable_thinking":true}
智谱 GLM              {"thinking":{"type":"enabled"}}
```

> 以上仅为示例，具体以厂商文档为准；填错可能导致接口 400，点「测试连接」可立刻验证。

模型被要求先简要分析、最后一行输出 JSON：`{"answer":"A"}`（多选如 `{"answer":"AC"}`），但脚本不依赖模型严格听话，解析时按以下顺序逐层尝试：

1. **JSON**：从后往前找最后一个合法 JSON，解析 `{"answer":"A"}` / `{"答案":"AC"}` / `{"result":"B"}` / `{"answer":["A","C"]}`；多选题优先读 `{"judge":{"A":true,"B":false,"C":true,"D":false},"answer":"AC"}` 里的逐选项判断
2. **显式前缀**：`答案` / `选项` / `应选` / `选择` / `answer` 后面的独立字母串，支持 `A、C`、`A and C`、`ABD`
3. **纯字母回复**：整段只有字母和分隔符，如 `A`、`BC`、`A,C`
4. **判断题**：识别 `正确` / `错误` / `不正确` / `√` / `×`，映射到对应选项
5. **选项文本回显**：模型直接复述选项内容时按文本匹配
6. **兜底独立字母**：用词边界匹配，不会把 `because` 里的 a/c 误当成答案

解析出的字母还会和当前题目的选项做校验，全部无效则判定失败、回退到默认选项。最近一次 AI 原始返回会显示在 AI 页状态栏，并写入 `sakt.quizlog` 的 `aiRaw` 字段。调试时可在控制台直接调用：

```js
__saktParse('答案是 C', { kindText: '单选题', stem: '', options: [
  { letter: 'A', text: '密封式' }, { letter: 'B', text: '防爆式' },
  { letter: 'C', text: '开启式' }, { letter: 'D', text: '以上都是' }
]})
// → ['C']
```

> 油猴环境优先用 `GM_xmlhttpRequest` 发请求，可绕开浏览器的跨域限制；直接注入/控制台模式会退回 `fetch`，需要接口本身允许 CORS。

### 提高正确率

平台按每个知识点的「答错数」判定是否通过，AI 答错同样计入，所以正确率值得调一调：

1. **先看状态里的 `AI 2/2` / `AI 3/3`**：`默认 · AI 失败` 表示请求没成功（超时、Key、模型名或参数错误），先解决这个再谈准确率
2. **「最大 tokens」给够**：默认 1024，思考模型 2048~4096。注意它是**输出上限**，不是「思考强度」——调大不会让模型想得更多，只会在被截断时兜底
3. **换大一点的模型**：`deepseek-chat`、`qwen-plus`、`glm-4.5` 这一档明显好于 `*-flash` / `*-turbo` / `*-mini`
4. **投票用 2+1**：先并发问 2 次，一致直接用；不一致自动补第 3 次。比固定 3 次省 1/3 请求，准确率基本不降
5. **多选题逐项计票**：脚本会让模型对 A/B/C/D 分别给出 true/false，再按选项合并多次投票（面板状态里的 `AI 2/2` 是最低单项票数）；「以上都是 / 以上都不对」会自动清掉同时选中的其他项，避免提交 ABCD 这种矛盾组合
6. **清空 AI 缓存**：旧版本或旧模型留下的答案可能一直复用；改完配置后点一次「清空缓存」

关于「联网」：对这类课程题库帮助很小——题目来自平台自己的题库，网上搜不到原题，各家联网参数也不统一。**思考模式可能有用，但必须配合足够的输出 tokens**；只想省事的话，保持 2+1 投票 + 1024 tokens 即可。

### 思考模式怎么开

DeepSeek 的 `deepseek-chat` **没有思考开关，也没有「思考强度」参数**；要用思考模式，把「模型」改成 `deepseek-reasoner`（或厂商对应的 `*-thinking` 模型），脚本会自动省略这类模型不支持的 `temperature`。

- 思考多少由模型自己决定，`max_tokens` 只是**上限**：设 2048 和 4096 不会让它「想得更深」，只影响会不会被截断
- 这些安全题单题思考量通常在几百 token，`max_tokens: 2048` 足够；超时建议 60000~120000
- 思考模型更慢、更贵：45 题考试用 2+1 可能要十几分钟，注意倒计时
- 如果换成 reasoner 后正确率没有明显提升，多半是题目本身有歧义或知识盲区，换更强的非思考模型、加第二模型交叉验证更有效

### 关于缓存：本地 / DeepSeek 端

- **本地缓存** `sakt.aiCache`：key = 接口地址 + 模型 + 题干 + 选项。命中时**一次请求都不发**；换模型或接口后旧答案自动失效，不会拿 A 模型的答案套 B 模型
- **DeepSeek 端**是上下文**前缀缓存**（prompt cache），不是答案缓存：相同的 system + 题目前缀在第 2/3 次请求时可能按缓存价计费，但答案每次都会重新生成，所以投票仍然是独立样本。前两次是并发发出的，大概率都 miss；不一致时补的第 3 次是串行的，最容易命中
- 命中情况会写进 `quizlog.aiCacheHit`（DeepSeek 的 `prompt_cache_hit_tokens` / OpenAI 的 `cached_tokens`），「测试连接」也会显示「缓存命中 N tokens」
- 这些题 prompt 只有几百 token，DS 缓存省下的钱基本可以忽略，不用为了它把并发改成串行

## 常见问题

**Q：AI 会不会答错？**
会。题目多是安全常识，主流模型准确率不低，但不保证。脚本会在 AI 失败时回退到「默认选项」，并把失败原因写进 `quizlog.aiError`。

**Q：AI 正确率低，要开联网或把思考调高吗？**
先看面板状态：`题库` 表示命中了平台标准答案；`AI 2/2` / `AI 3/3` 表示模型作答；`默认 · AI 失败` 表示请求根本没成功。能成功但准确率低，按顺序调整：最大 tokens 1024~2048 → 换 `deepseek-chat`/`qwen-plus` 这一档模型 → 投票 2+1 → 清空 AI 缓存。联网搜索对平台题库几乎没用（网上没有原题），不建议折腾。DeepSeek 的 `deepseek-chat` 没有思考开关，要思考换 `deepseek-reasoner`；`max_tokens` 是输出上限，不是「思考强度」，2048~4096 足够。**如果导入了题库，优先看是不是题库命中——那比任何模型都准。**

> 旧版（≤1.3.x）的 `max_tokens` 只有 32，思考模型经常返回空内容并回退默认 A——那些题**不是模型答的**。更新后请用 `quizlog` 里的 `source` / `aiError` 判断真实情况。

**Q：考试页能自动答吗？**
可以，见「考试自动答题」。模拟考试不计成绩；正式考试平台有「不要作弊」提示，是否使用请自行判断，风险自负。答题中途刷新页面会丢失当前进度。

**Q：API Key 安全吗？**
Key 只保存在本机 `localStorage['sakt.config']`，不会发给学校平台；但同源页面脚本理论上可读，公用电脑上不建议保存。

**Q：会被判定作弊吗？**
不知道。视频是真实按倍速播放的，进度由平台自己的接口上报；但「自动点击、自动答题」本身属于自动化行为，是否合规取决于学校规定，**风险自负**。

**Q：为什么不用直接调接口秒刷？**
那样等于伪造学习记录。本脚本刻意不这么做——它只加速「人不用盯着」这件事，不跳过内容。

**Q：卡住不动 / 切不到下一节？**
刷新页面即可，队列会保留并自动续跑。若某节课目录结构特殊导致点不到，脚本会依次回退到 SPA 路由跳转、整页跳转。

**Q：安装后课程页一直刷新 / 像卡死？**
1.2.1 之前存在启动竞态：页面刚加载时课程标题还没渲染，脚本误判「当前课时不在队列」而反复跳转。1.2.2 已修复：先等待标题和目录树渲染，对整页跳转做 10 秒防抖，并且 60 秒内整页加载超过 3 次会自动停止自动启动（面板会提示，手动点「开始」即可）。更新脚本后强刷一次页面。

**Q：支持其他学校/平台吗？**
目录、接口、DOM 都是该平台（杰畅教育系统）专有的，其他平台需要改 `@match`、接口路径和选择器。
